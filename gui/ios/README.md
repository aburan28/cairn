# cairn for iPhone

A native reader for a cairn node. The same job as the site at `/ui/` — what
this node will pay for, whether you have forked, every record as stored —
without a browser chrome and without pretending to be a node.

It does **not** run the researcher. That is [gui/macos](../macos): Python, a C
compiler, and a write lock on a log. None of those fit in an App Store sandbox,
and a phone that claimed to settle claims would be a third implementation of
the rules. This app only reads.

```sh
open gui/ios/Cairn.xcodeproj     # Xcode, then Run on a simulator or a phone
swift test --package-path gui/ios
```

The Xcode project is the `.app`. The Swift package is the decoder, the chain
check, and the same SwiftUI scenes compiled as a macOS window so CI can fail
a view without a simulator. `make ios-check` runs the package tests.

## What it shows

**Overview.** Live stats when a node answers — objectives, open, pool, paid,
chain links — each labelled with where it came from. When nothing answers,
the [launch snapshot](../../launch/) that the public site uses, and the page
says so. The merkle root and the `cairn audit` command sit at the bottom,
same as the landing page.

**Objectives.** Searchable, settled hideable, reward-first. A challenge shows
the statement as untrusted text, the current frontier, and the successive
states that built it (`buildMoves` — the same join as `/frontier` on the
site). The one arithmetic check a reader can do for itself: whether paid +
remaining exceeds the reward.

**Chain.** Head, height, ledger head. Walks the links and reports the first
whose `prev` is not the one before it. A break is shown in red and the head
is called untrustworthy. Nothing here re-derives the fold.

**Log.** NDJSON, parsed per line. A bad line is named and the rest still
render. Expand a row for the record as stored. The fetch waits until a node
has actually answered — assigning a resolved URL is not the same as live.

**Peers.** Announcements in the log, not live sessions. The copy says so.

**How it works.** The protocol in one screen. The long form stays on the
site; this is not a second copy of the payout curve.

**Settings.** The node URL, and the last few that answered. Cleartext HTTP
is allowed because an operator's node is often on a LAN or an SSH tunnel,
and refusing it would make the app unable to read the one thing it exists
to read.

## Nothing on it is simulated

The fallback is `Sources/CairnKit/Resources/snapshot.json`, a copy of
`ui/lib/snapshot.json`, generated by `scripts/site-snapshot.sh` from
`launch/cairn.jsonl`. Regenerating the site snapshot copies this file too.
A test requires the copy to decode, so a field rename in `GET /objectives`
fails here the same way it fails the site.

## Requirements

iOS 17 or newer, Xcode 15 or newer. The package tests also run on macOS 14.

Point the app at a node that serves HTTP (`cairn serve` or `cairn run`).
Writes — posting a challenge, submitting a claim — stay on the node's own
origin. Use the site at `/ui/submit` or the CLI.
